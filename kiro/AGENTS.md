# 给 AI 助手的安装指令（Kiro / Cursor 等）

> 正常情况下不要用这个文件。桌宠的标准安装入口是 Skill：`<Skill 目录>/scripts/install-pet.sh`，说明在 Skill 目录的 `SKILL.md`。
> 只有当你手上**只有这一个目录**（例如单独拿到源码副本）、拿不到 Skill 时，才按下面的步骤走。

用户把这个目录交给你，意图是**在本机安装 Kiro 桌宠并启动**。请直接按下面步骤执行，不需要再向用户确认安装意图。

## 这是什么

macOS 专用的桌面小挂件：读取本机 Kiro 日志，把每个 AI 会话的运行状态显示成桌面上的像素小狗（在跑哪个任务、跑了多久、成功还是报错），并在完成/异常时发系统通知。纯本地运行，不上传任何数据。

## 执行步骤

### 1. 定位项目目录

本文件位于源码目录根部（同级有 `app.py`、`kiro_pet/`、`scripts/`）。把该目录放在一个固定位置即可，脚本会自动适配路径。

**不要放在 `/tmp` 之类的临时目录**，登录自启会失效。若目标目录不存在先 `mkdir -p`。

### 2. 安装并启动

```bash
cd "<项目目录>"
./scripts/install.sh
```

这一步会自动完成：挑选可用的 python3 → 建立独立虚拟环境 → 安装唯一依赖 PyObjC → 校验 Cocoa 可用 → 生成登录自启配置 → 启动桌宠。全程无需交互，不需要 sudo。

### 3. 验证

```bash
./scripts/verify.sh
```

**判定标准是退出码 0 且没有 `[FAIL]`**。`[WARN]` 表示可选项缺失（未装 terminal-notifier、本机没装 Kiro、用了 `--no-autostart`），不算安装失败，结论行会给出通过与提示的项数。有 `[FAIL]` 时按下面的故障对照处理。

### 4. 告知用户

安装成功后请转述这三点：

1. 屏幕右下角出现像素小狗，顶部菜单栏出现 Kiro 白色小恶灵图标。
2. **点任务名跳转会话需要授权**：首次点击时 macOS 会弹权限请求，需在「系统设置 → 隐私与安全性 → 辅助功能」中允许项目目录下的 `.venv/bin/python`。未授权时该功能自动降级为只把 Kiro 调到前台，其余功能不受影响。
3. **可选增强**：`brew install terminal-notifier` 可获得可点击、不自动消失的通知；不装则退回系统通知，只是点了不会跳转。

其余用法让用户看项目里的 `QUICKSTART.md`。

## 用户想用自己宠物的照片做形象

用户给一张宠物照片并希望换成自己的宠物时，执行：

```bash
cd "<项目目录>"
./.venv/bin/python scripts/make_photo_pet.py --photo "<照片绝对路径>" --name "<显示名称>"
```

参数说明：
- `--photo` 必填，宠物照片路径。用户给的是聊天附件时，先让用户把图存到磁盘（例如桌面）并确认路径，不要自己编路径。
- `--name` 显示名称，会出现在菜单里，例如「我家狗」。省略时用文件名。
- `--id` 可选，皮肤 ID（英文），默认从名称或文件名推导。
- 命令会输出到 `~/Library/Application Support/Kiro Desktop Pet/pets/<id>/`，不写项目目录。

脚本自动完成四步，全部本地运行、不联网、不花钱：抠出主体 → 识别 24 个关节点 → 按关节点分层清理背景残留 → 生成 6 种状态共 54 帧动画。耗时约十几秒。

完成后告知用户：**菜单栏 Kiro 小恶灵 → 更换形象 → 选刚生成的名字**，即可切换；随时可以切回「像素小狗」。

照片要求（不满足时脚本会直接报错并说明原因，把原因转述给用户并让他换图）：
- 正面、四肢可见，坐姿或站姿
- 主体和背景明暗有区分（纯白宠物站白墙前会抠不干净）
- 主体占画面一半以上
- 主体不要紧贴人腿、家具等其他物体

必须如实告知用户的两个限制：
- 照片形象**没有表情变化**（照片无法伪造眨眼和情绪），生气、开心靠整体动作体现
- 照片形象**没有局部动作**（摇尾巴、单独抖耳朵做不到），动作是整体的呼吸、弹跳、跳跃、抖动、垂头、蜷卧
- 想要表情和局部动作需要手绘像素风，那是内置「像素小狗」的做法，无法自动生成

用户想删掉某个形象时，直接删除对应目录即可：`rm -rf ~/Library/Application\ Support/Kiro\ Desktop\ Pet/pets/<id>`，菜单会自动不再列出。

## 故障对照

| 现象 | 处理 |
| --- | --- |
| 提示找不到 Python 3.10+ | 桌宠依赖 PyObjC 12，只支持 3.10 及以上；macOS 自带的是 3.9，用不了。让用户执行 `brew install python@3.13`（或从 python.org 下载安装包）后重跑 install.sh |
| 生成形象提示需要 macOS 14+ | 照片抠图与姿态识别用的是 macOS 14 才有的 Vision 能力，旧系统只能用内置像素小狗，桌宠其余功能不受影响 |
| pip 安装 PyObjC 失败 | 网络或 pip 源问题，重试或让用户配置可用的 pip 源后重跑 |
| 提示未找到 Kiro.app | 正常，桌宠会显示离线状态；装好 Kiro 后自动恢复，无需重装 |
| verify 显示进程未运行 | 执行 `./scripts/start.sh`，再看 `tail -30 ~/Library/Logs/'Kiro Desktop Pet'/pet.log` |
| 生成形象报「没检测到前景主体」或「关节置信度不足」 | 照片不符合要求，让用户换一张正面、清晰、主体占比大的照片 |
| 菜单里看不到新形象 | 确认脚本输出目录下有 `skin.json` 和 `frames/`，然后重开菜单（菜单每次打开都会重新扫描） |
| 小狗看不见 | 从菜单栏 Kiro 小恶灵选「显示桌宠」；若已收起在屏幕边缘，选「展开桌宠」或单击侧边栏 |

## 边界

- 只支持 macOS，不要尝试在其他系统安装。
- 不需要 sudo，不要修改系统配置，不要改动 Kiro 自身的数据或设置。
- 不要把项目装进临时目录（如 `/tmp`），登录自启会失效。
- 如需卸载：`./scripts/uninstall.sh`（仅移除自启，保留设置和日志）。
- 桌宠只读 Kiro 的日志与会话存档，不写入、不上传；不要改动 Kiro 自身的数据与设置。
